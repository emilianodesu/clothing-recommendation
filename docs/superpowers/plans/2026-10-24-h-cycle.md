# H cycle validation implementation plan

> **For agentic workers:** use superpowers:executing-plans task by task.

**Goal:** Observe one real H build under API load with bounded clock uncertainty.
**Architecture:** Reuse the existing host load generator and scheduler, with an
independent reservation, instrumented child, recovery and aggregate archive.
**Tech Stack:** Python standard library, existing Docker/Colima, GitHub CLI.
**Spec:** [h-cycle-v1](../../mac24-h-cycle.md). The user authorized continuing
this validation; implement in this session and review before operational use.

## Global constraints

Preserve historical T8-B failed, T8-C reservation and H selection; no training,
test evaluation or activation. 20 req/s, 120+600 s, p95 <200 ms, errors <1%,
≥20 conservative arrivals; one build. Keep resources and exact original services.

## Review focus

Clock-origin mismatch and empty overlap; omitted requests masking errors;
SSH interruption with a surviving child; recovery continuing after one failure;
new UI generation mistaken for historical UI. These require executable tests.
